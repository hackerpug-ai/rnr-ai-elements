# E2E / Human Testing Criteria — rnr-ai-elements MVP

Version 1.0.0 · 2026-09-01

Every acceptance criterion in every use case has at least one criterion here. Each carries
an observable pass condition — no "it should work".

**The determinism rule applies to every row.** Where a criterion involves streaming, the
setup replays a committed `UIMessageStream` fixture and the assertion is on the engine's
outcome (scroll position, badge text, throttle behavior), never on the model's prose.

## The five criteria that actually decide the project

Everything above is necessary; these five are the ones that, if any fails, mean the
promises in `00-overview.md` are not kept:

1. **The theming flip.** Swap the consumer's `global.css` for a loud alternate palette
   (magenta primary, non-default radius), clear the Metro cache, rebuild, screenshot chat +
   agent + tool-approval on iOS **and** Android in **both** schemes. Six pairs. Every pixel
   must move. Anything that does not move is a hardcoded value — most likely inside a
   markdown or syntax-highlight style object.
2. **The side-by-side.** An RNR demo screen and an AI Elements chat screen on one phone. A
   reviewer must not be able to say which library drew which surface.
3. **The clean-app install.** Every registry item installs via the RNR CLI into a fresh
   Expo 57 app and typechecks. This is what "distributes exactly like RNR" reduces to.
4. **The 500-message scroll.** A real transcript, mid-range Android, keyboard open,
   streaming. Pinned at the bottom, releases on scroll-up, steady frame rate.
5. **The gated tool call.** A real provider requests approval; the card renders with
   thumb-sized controls; approving calls back and the resolved state persists in the
   transcript. Without this, a gated agent stalls forever and nothing else in AGENT matters.

## Maintenance

Criterion IDs are stable. Adding an AC appends a criterion; it never renumbers existing
ones. Removing an AC retires its criterion rather than reusing the ID.
