## What this does

Extend the restore logic in `tests/sprint-01-docs-spike-skeleton/gallery-manifest-dual-emit.test.ts`
so the delete-dir case also restores the **gitignored prebuild artifact**
`apps/docs/src/data/registry-items.json`, exactly as the existing `familiesBytes` snapshot
pattern (FIX-SHELL-001-1) restores `families.json`.

## Why

The test's delete-dir case does `rmSync(DATA_DIR, { recursive: true, force: true })` and
afterwards restores ONLY `families.json` (`writeFileSync(FAMILIES_JSON, familiesBytes)` at
gallery-manifest-dual-emit.test.ts:121-123). `registry-items.json` — generated by
`pnpm registry:build`, read by pages and by sibling tests — stays MISSING after the run.
Any vitest executed after this file in the same run (or any later same-checkout consumer)
finds the prebuild gone. FAM-002's cycle-1 review hit this live: full `vitest run` returned
668/669 with a failure attributable to this ordering; FAM-002's own implementer run saw 669/669.
Orchestrator verified the mechanism directly: the rmSync sits at
gallery-manifest-dual-emit.test.ts:115 and the restore block covers only families.json.

## How to verify

```
sh -c 'test -f apps/docs/src/data/registry-items.json && pnpm vitest run tests/sprint-01-docs-spike-skeleton/gallery-manifest-dual-emit.test.ts && test -f apps/docs/src/data/registry-items.json; echo exit=$?'
```

Exits 0 with the prebuild present before AND after the run (byte-identical when it existed).
`git status --porcelain -- apps/docs/src/data/` stays empty (registry-items.json is gitignored —
presence/bytes, not git, is the assertion).
